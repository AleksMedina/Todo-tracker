# Трекер студенческих задач

Учебный проект к домашнему заданию 1: веб-приложение (список дел на семестр), развёрнутое в Docker-контейнере на облачной виртуальной машине. Сборка, упаковка и деплой выполняются автоматически (CI/CD), состояние приложения и сервера отслеживается в Grafana.

## Что делает приложение

- Добавление задачи: название, дедлайн (дата и время), приоритет, цвет. Отметка выполнения чекбоксом, удаление.
- Задачи разложены по блокам: «Горит», «Высокий приоритет», «Остальные», «Выполнено».
- Автосортировка: сначала просроченные, затем со сроком меньше 24 часов, затем остальные. Внутри группы порядок по приоритету, затем по дедлайну.
- Чекбоксы с красной рамкой и зелёной галочкой, цвет рамки настраивается для каждой задачи и по умолчанию.
- Данные хранятся в SQLite на volume Docker, поэтому переживают перезапуск и деплой новой версии.

Стек: Python 3.12, Flask, Gunicorn, SQLite, prometheus_client. Инфраструктура: Docker, Docker Compose, GitHub Actions, GitHub Container Registry, Prometheus, Grafana, cAdvisor, node-exporter.

## CI/CD

1. **build** (`scripts/build.sh`): ставит зависимости в виртуальное окружение, запускает автотесты (pytest) и упаковывает приложение в `dist/todo-app.tar.gz`. Архив загружается как артефакт запуска.
2. **package**: берёт этот артефакт, собирает по `Dockerfile` образ и публикует его в GHCR с тегами `<sha коммита>` и `latest`.
3. **deploy**: копирует на сервер `docker-compose.yml`, `monitoring/` и `scripts/`, запускает `scripts/deploy.sh`. Скрипт скачивает образ, обновляет контейнеры и ждёт статуса `healthy`. Если приложение не поднялось, пайплайн завершается ошибкой и выводит логи.

На Pull Request выполняется только задача `build`. Деплой идёт только из ветки `main`.

## Мониторинг

Prometheus опрашивает три источника каждые 15 секунд: приложение (`/metrics`), cAdvisor (контейнеры) и node-exporter (сервер). Дашборд подключается к Grafana автоматически (provisioning), в репозитории лежит его JSON.
