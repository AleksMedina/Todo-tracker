# Трекер студенческих задач (To-Do List)

Flask + SQLite, развёрнутый в Docker. CI/CD на GitHub Actions, мониторинг на Prometheus + Grafana.

- **Интерфейс:** поле ввода, дедлайн (дата и время), приоритет, цвет, кнопка «Добавить», чекбоксы, удаление задачи.
- **Блоки:** «Горит», «Высокий приоритет», «Остальные», «Выполнено». Пустые блоки скрываются.
- **Автосортировка:** срочное и важное поднимается наверх (правила ниже).
- **Чекбоксы:** красная рамка и зелёная галочка; цвет рамки меняется для каждой задачи и по умолчанию.
- **Health check:** `GET /health` проверяет, что SQLite читается и каталог с БД доступен для записи (200 или 503).
- **Метрики использования:** `todo_tasks_added_total`, `todo_tasks_completed_total`, `todo_page_visits_total` (в Grafana: «в час» через `increase(...[1h])`).
- **Ресурсы:** контейнер приложения (cAdvisor) и сервер (node-exporter): занято и доступно.

## Блоки, приоритеты и сортировка

Задача имеет приоритет (высокий, средний, низкий) и необязательный дедлайн. Сервер отдаёт список уже отсортированным
(`GET /api/tasks`), страница обновляет его каждые 30 секунд, поэтому задачи сами «поднимаются» по мере приближения срока.

Порядок невыполненных задач:

1. просроченные (дедлайн уже прошёл);
2. до дедлайна меньше 24 часов;
3. все остальные.

Внутри каждой группы задачи идут по приоритету (высокий выше), затем по дедлайну (ближе выше). Выполненные уходят в блок «Выполнено».

| Блок | Что попадает |
|---|---|
| Горит | просроченные и со сроком меньше суток |
| Высокий приоритет | остальные задачи с высоким приоритетом |
| Остальные | средний и низкий приоритет |
| Выполнено | отмеченные чекбоксом |

Время дедлайна вы вводите в своём часовом поясе, в базе оно хранится в UTC.

## Цвета квадратиков

- Цвет конкретной задачи: кружок справа от неё (или поле «Цвет» при создании).
- Цвет по умолчанию: блок «Цвета квадратиков» внизу страницы. Он хранится в браузере (localStorage), красный по умолчанию.
- «Сбросить цвета у всех задач» убирает персональные цвета, и все квадратики берут цвет по умолчанию.
- Галочка всегда зелёная.

## API

| Метод и путь | Назначение |
|---|---|
| `GET /api/tasks` | список в порядке сортировки, у каждой задачи поле `status`: `overdue`, `soon`, `normal`, `done` |
| `POST /api/tasks` | `{title, priority: 1..3, deadline: ISO 8601, color: "#rrggbb"}`, нужен только `title` |
| `PATCH /api/tasks/<id>` | любые из полей `done`, `priority`, `deadline` (null очищает), `color` (null сбрасывает) |
| `POST /api/tasks/reset-colors` | сбросить цвета у всех задач |
| `DELETE /api/tasks/<id>` | удалить |

Обновление с прошлой версии: при старте приложение само добавляет в таблицу колонки `priority`, `deadline`, `color`.
Уже сохранённые задачи остаются, им ставится средний приоритет и нет дедлайна.

## Структура

```
app/                    приложение (main.py, templates/index.html, tests/)
Dockerfile              описание контейнера
docker-compose.yml      app + Prometheus + Grafana + cAdvisor + node-exporter
scripts/build.sh        сборка: зависимости, тесты, артефакт dist/todo-app.tar.gz
scripts/deploy.sh       деплой на сервере: pull образа, up -d, ожидание healthy
.github/workflows/ci-cd.yml   пайплайн: build -> package -> deploy
monitoring/             конфиг Prometheus и дашборд Grafana (подключаются автоматически)
```

## Быстрый запуск из исходников (для проверки)

Нужны Docker с плагином Compose, для `build.sh` ещё `python3` и `python3-venv`.

```bash
git clone <URL_РЕПОЗИТОРИЯ> && cd todo-tracker
./scripts/build.sh                 # тесты + артефакт dist/todo-app.tar.gz (необязательно локально)
docker compose up -d --build       # собирает образ и поднимает всё
```

| Что | Адрес |
|---|---|
| Приложение | http://localhost:8000 |
| Health check | http://localhost:8000/health |
| Метрики приложения | http://localhost:8000/metrics |
| Дашборд Grafana (просмотр без логина) | http://localhost:3000 |
| Prometheus | http://localhost:9090 |

Редактирование в Grafana: логин `admin`, пароль из `GRAFANA_PASSWORD` (по умолчанию `admin`, задайте свой в `.env`).
Остановить: `docker compose down` (данные сохраняются в volume), с удалением данных: `docker compose down -v`.
